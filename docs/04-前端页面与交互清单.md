# 前端页面与交互清单

**项目**：localcraft — 内网工具 / Skill 共享平台
**技术栈**：Vite + React 18 + TypeScript + Tailwind CSS + shadcn/ui
**设计目标**：内网环境下「打开即找得到、看一眼就知道是什么、点一下就能拿到」的工具导航门户

---

## 1. 技术选型

| 关注点 | 选择 | 理由 |
| --- | --- | --- |
| 构建 | Vite 5 | 冷启动与 HMR 快，构建产物为纯静态，由后端托管 |
| 框架 | React 18 + TypeScript（`strict: true`） | shadcn/ui 原生基于 React，无适配层 |
| 样式 | Tailwind CSS v4 + shadcn/ui 的 CSS 变量体系 | 令牌集中管理，明暗主题零成本 |
| 组件 | shadcn/ui（Radix UI 底座） | 组件源码进仓库，可自由改；Radix 自带无障碍与键盘支持 |
| 路由 | React Router v6（`createBrowserRouter`） | 支持数据 API 与嵌套路由 |
| 服务端状态 | TanStack Query v5 | 缓存、重试、乐观更新、失效策略开箱即用 |
| 表单 | react-hook-form + zod | 与 shadcn 的 `Form` 组件天然集成；zod schema 可复用于类型推导 |
| HTTP | 原生 `fetch` 封装（不引入 axios） | 需求简单，少一个依赖；统一拦截 401 与错误格式 |
| Markdown 渲染 | markdown-it + DOMPurify | 详情、变更说明、公告统一走同一条渲染管线 |
| 代码高亮 | Shiki（按需加载） | 详情里的代码块；比 highlight.js 输出更干净 |
| 图标 | lucide-react | shadcn 默认图标库 |
| 日期 | date-fns | 体积小，按需引入 |
| 通知 | sonner（shadcn 推荐） | toast |
| 表格 | TanStack Table + shadcn `DataTable` | 管理台的用户/工具列表需要排序、筛选、分页 |
| E2E | Playwright | 核心流程回归 |

**不引入的东西**：状态管理库（Redux/Zustand）不需要 —— 服务端状态交给 TanStack Query，UI 局部状态用 `useState`，全局只有「当前用户」和「主题」，用 Context 即可。少一层抽象。

### 3.3 间距与栅格

- 间距基准单位 4px（Tailwind 默认）
- 页面容器：`mx-auto w-full max-w-[1400px] px-4 sm:px-6 lg:px-8`
- 门户卡片栅格：`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4 gap-4`
- 管理台表格页：内容区固定 `max-w-[1400px]`，表格横向可滚动
- 圆角：卡片 `rounded-xl`，按钮/输入框 `rounded-lg`（由 `--radius` 派生）
- 阴影：卡片默认无阴影 + `border`，hover 时 `shadow-md` + `-translate-y-0.5`，过渡 150ms。**不用大面积重阴影**，保持内敛

### 3.4 明暗主题

- 默认跟随系统：`prefers-color-scheme`
- 顶栏提供切换（浅色 / 深色 / 跟随系统三态），选择存 `localStorage`
- 在 `index.html` 里放一段**阻塞式内联脚本**，在 React 挂载前根据 localStorage 设置 `<html class="dark">`，避免首屏白闪。这是唯一允许的内联脚本。
  **CSP 放行方式（M1 checkpoint 裁定，2025-03 修订）**：用 **sha256 哈希**，不用 nonce。原因是 `dist/index.html` 是静态文件，无法携带每请求 nonce；为注入 nonce 而把 index.html 模板化会破坏其可缓存性并让后端托管逻辑复杂化。该内联脚本内容固定，哈希稳定。M3 配置 nginx CSP 头时按此哈希放行（构建产物校验脚本需记录该哈希）。

## 4. 路由表

```tsx
const router = createBrowserRouter([
  { path: "/login", element: <LoginPage /> },
  {
    // 注意：AppShell **不**包 RequireAuth —— 门户首页与工具详情允许匿名访问
    element: <AppShell />,
    children: [
      /* 公开层：匿名可看，是否放行由 meta.allow_anonymous_view 决定 */
      {
        element: <AllowAnonymous><Outlet /></AllowAnonymous>,
        children: [
          { path: "/", element: <PortalPage /> },
          { path: "/tools/:slug", element: <ToolDetailPage /> },
        ],
      },
      /* 以下需要登录 */
      {
        element: <RequireAuth><Outlet /></RequireAuth>,
        children: [
          { path: "/change-password", element: <ChangePasswordPage /> },
      {
        path: "/me",
        element: <RequireRole roles={["user","approver","superadmin"]} />,
        children: [
          { index: true, element: <ProfilePage /> },
          { path: "tools", element: <MyToolsPage /> },
          { path: "tools/new", element: <ToolEditorPage mode="create" /> },
          { path: "tools/:id/edit", element: <ToolEditorPage mode="edit" /> },
          { path: "tools/:id/versions", element: <VersionsPage /> },
        ],
      },
      {
        path: "/admin",
        element: <RequireRole roles={["approver","superadmin"]} />,
        children: [
          { index: true, element: <OverviewPage /> },
          { path: "approvals", element: <ApprovalsPage /> },
          { path: "approvals/history", element: <ApprovalHistoryPage /> },
          { path: "tools", element: <ToolsAdminPage /> },
          { path: "categories", element: <CategoriesPage /> },
          { path: "tags", element: <TagsPage /> },
          { path: "users", element: <RequireRole roles={["superadmin"]}><UsersPage /></RequireRole> },
          { path: "groups", element: <RequireRole roles={["superadmin"]}><GroupsPage /></RequireRole> },
          { path: "whitelist", element: <RequireRole roles={["superadmin"]}><WhitelistPage /></RequireRole> },
          { path: "tokens", element: <RequireRole roles={["superadmin"]}><TokensPage /></RequireRole> },
          { path: "settings", element: <RequireRole roles={["superadmin"]}><SettingsPage /></RequireRole> },
          { path: "import-export", element: <RequireRole roles={["superadmin"]}><ImportExportPage /></RequireRole> },
          { path: "recycle-bin", element: <RequireRole roles={["superadmin"]}><RecycleBinPage /></RequireRole> },
        ],
      },
      { path: "*", element: <NotFoundPage /> },
    ],
  },
]);
```

**三态守卫**：`RequireAuth` 与 `AllowAnonymous` 都区分 `unknown`（会话/站点配置未就绪 → 全屏 loader，不闪登录页）/ `authenticated` / `unauthenticated`。区别只在匿名分支：`RequireAuth` 一律跳 `/login`；`AllowAnonymous` 再看 `meta.allow_anonymous_view` —— 为 `true` 放行，为 `false` 或 `/meta` 取不到时跳 `/login`（**取不到按不放行处理**，宁可让访客多点一次登录，也不要在"不知道该不该公开"的状态下把门户露出去）。

**路由守卫不是安全边界**：`RequireRole` 只做「不给看」的体验优化，真正的权限在服务端。角色为 `approver` 的用户即使手输 `/admin/users`，接口也会返回 403。

**强制改密拦截**：`RequireAuth` 里检查 `user.must_change_password`，为真时除 `/change-password` 与 `/login` 外的所有路由重定向到改密页。同时在 `api/client.ts` 里拦截 `403 PASSWORD_CHANGE_REQUIRED`，兜底处理。

## 6. 页面详述

### 6.1 `/login` — 登录

**布局**：居中卡片，`min-h-screen grid place-items-center`，背景为极淡的径向渐变（`bg-gradient-to-br from-background to-accent/30`），不做花哨插画。

**组件**：`Card` > `CardHeader`（站点名 + 一句说明） + `CardContent`（`Form`）

**字段**：用户名（`Input`，autoFocus）、密码（`Input type="password"` + 显隐切换按钮）

**交互**：

| 场景 | 行为 |
| --- | --- |
| 提交中 | 按钮 `disabled` + `Loader2` 旋转图标 |
| 凭证错误 | 表单顶部 `Alert variant="destructive"` 显示「用户名或密码错误」，**不清空密码框**，聚焦到密码框并全选 |
| 账号锁定 | `Alert` 显示倒计时「账号已锁定，请 12:34 后重试」，按钮置灰直到倒计时结束 |
| 账号禁用 | `Alert` 显示「账号已禁用，请联系管理员」 |
| 需改密 | 登录成功后直接 `navigate('/change-password', { replace: true })` |
| 已登录访问 | 重定向到 `?redirect=` 指定的路径或 `/` |

**安全细节**：`autoComplete="username"` / `"current-password"` 让密码管理器正常工作；不使用 `type="text"` 伪装密码框。

---

### 6.2 `/change-password` — 强制改密

**两种模式**：

- 强制模式（`must_change_password = true`）：只显示改密表单，无「跳过」按钮，顶栏的导航项全部隐藏
- 主动模式（用户从菜单进入）：显示返回按钮

**字段**：原密码、新密码（带强度指示条）、确认新密码

**密码强度指示**：实时计算并显示 4 段进度条 + 文案（弱 / 一般 / 强 / 很强）。规则与服务端一致（长度 ≥ 10，含 4 类字符中的 3 类）。提交前用 zod 校验，**同时服务端再校验一次**（前端校验只是体验）。

**成功后**：toast 提示「密码已更新，请重新登录」→ 清空本地 token → 跳登录页。这是刻意的：改密后旧会话全部吊销，强制重新登录能让用户确认新密码可用。

**历史版本上限提示**：顶部显示「历史版本保留 10 份，当前 4 份」。接近上限时（≥8）变 `warning` 色并提示「再上传 N 个版本将开始归档最旧的版本」。

**关键设计点**：

| 设计 | 理由 |
| --- | --- |
| 等待时长高亮 | 超过 24 小时显示 `warning` 图标；超过 72 小时显示 `destructive`。让积压自己浮现，不依赖审批人主动查看 |
| 左侧列表项显示变更说明首行 | 让审批人不用点开就能判断大部分简单情况，批量批准才真正可用 |
| `[全部] [新工具] [新版本]` 分段筛选 | 审批人常按类型批处理。新工具需仔细看，新版本通常快审 |
| 右侧抽屉而非新页面 | 保持列表上下文，处理完一条立刻看下一条，不用来回导航 |
| 批量批准按钮显示已选数量 | 避免误操作 |
| **无批量驳回** | 驳回必须逐条写理由（SRS FR-APPR-09）。界面不提供该按钮，而不是提供了再报错 |
| 键盘快捷键 | `J`/`K` 上下切换条目，`A` 批准，`R` 驳回，`Esc` 关闭抽屉。高频操作者的效率提升明显 |
| 审批后自动前进 | 批准后自动选中下一条并 toast 提示，不弹二次确认（批准是低风险操作，且可下架补救） |
| 驳回需二次确认 | 弹 `AlertDialog` 展示理由内容让用户确认，因为驳回对提交者影响大 |

**详情预览联动**：抽屉内直接复用工具详情页的渲染组件（`Markdown`、`SkillPreview`、`ImageGallery`），**不跳转到门户**。这是为了不让审批人在两个上下文之间切换。

## 7. 通用组件

### 7.1 `Markdown`

统一出口，所有 Markdown 渲染都走它：

```tsx
export function Markdown({ source, className }: Props) {
  const html = useMemo(() => {
    const raw = md.render(source ?? "");
    return DOMPurify.sanitize(raw, {
      ALLOWED_TAGS: [...],          // 白名单，不含 script/iframe/style
      ALLOWED_ATTR: ["href","title","class","target","rel"],
      ALLOWED_URI_REGEXP: /^(?:https?|mailto):/i,   // 禁 javascript: / data:
    });
  }, [source]);
  return <div className={cn("prose prose-sm dark:prose-invert max-w-none", className)}
              dangerouslySetInnerHTML={{ __html: html }} />;
}
```

**要点**：
- `markdown-it` 配置 `html: false`（不允许原始 HTML），双保险
- 外链一律加 `target="_blank" rel="noopener noreferrer"`
- 代码块懒加载 Shiki 高亮，避免首屏引入高亮引擎
- 用 `@tailwindcss/typography` 的 `prose` 类做排版基线，避免手写一堆样式

### 7.2 `ToolCard`

见 6.3。是首页复用度最高的组件，需要支持三种尺寸（网格标准、网格紧凑、列表行）—— 通过 `variant` prop 控制，而不是写三个组件。

### 7.3 `DownloadButton`

封装「申请票据 → 触发下载 → 失败提示」的完整链路：

```tsx
function DownloadButton({ slug, versionId, disabled, reason }: Props) {
  const [pending, setPending] = useState(false);
  const toast = useToast();

  async function handleClick() {
    setPending(true);
    try {
      const ticket = await post(`/tools/${slug}/download-ticket`, { version_id: versionId });
      const a = document.createElement("a");
      a.href = ticket.url;
      a.download = ticket.file_name;
      document.body.appendChild(a); a.click(); a.remove();
      toast.success(`开始下载 ${ticket.file_name}`);
    } catch (e) {
      toast.error(getErrorMessage(e));
    } finally {
      setPending(false);
    }
  }
  // disabled 时用 Tooltip 说明原因
}
```

### 7.4 `EmptyState` / `ErrorState` / `PageSkeleton`

三个状态组件必须**在所有列表页统一使用**，不允许各页面自己写一套。参数为图标、标题、描述、可选操作按钮。统一的好处是空态文案风格一致，且未来要改整体调性时只改一处。

### 7.5 `StorageUsageBar`

`Progress` + 文案「已用 1.2 GB / 2.0 GB（60%）」。颜色阈值：< 70% primary，70~90% warning，> 90% destructive。

### 7.6 `CopyButton`

`Button variant="ghost" size="icon"` + `Copy`/`Check` 图标切换，点击后图标变 `Check` 并保持 2 秒。用 `navigator.clipboard.writeText`，失败时降级到 `document.execCommand`。

### 7.7 `ConfirmDialog`

对危险操作统一封装：标题、描述、确认文案（要求输入资源名才能确认的高危操作单独实现）、`variant="destructive"`。

### 7.8 `usePermission`

```tsx
const { can } = usePermission();
{can("tool:create") && <Button>上传工具</Button>}
```

权限点从 `/auth/me` 的 `permissions` 数组读。**再次强调**：这仅用于 UI 显隐，服务端是唯一权威。

## 8. 无障碍与响应式

### 8.1 无障碍

- 所有可点击元素用语义标签（`<button>` / `<a>`），不用 `<div onClick>`
- 表单字段必须有 `<FormLabel>`；错误用 `<FormMessage>`（shadcn 已通过 `aria-describedby` 关联）
- 图标按钮必须带 `aria-label` 或可见文本（`DownloadButton` 的 `aria-label="下载 日志分析器"`）
- 模态框用 Radix 的 `Dialog`/`Sheet`，自带焦点陷阱与 `Esc` 关闭
- 焦点可见：全局 `focus-visible:ring-2 ring-ring ring-offset-2`，**不要 `outline: none`**
- 跳转到主内容链接（Skip to content），Tab 首次按下时出现
- 图片 `alt` 文本必填（上传时可选填，为空则用工具名 + 序号兜底）
- 状态徽标不能只靠颜色区分 —— 必须同时有文字（如「已发布」而不是一个绿点）

### 8.2 响应式

| 断点 | 门户 | 详情 | 管理台 |
| --- | --- | --- | --- |
| `< sm` (640) | 单列卡片；筛选折叠为 `Sheet`；搜索框全宽 | 单列，右侧信息栏移到顶部 | 侧栏折叠为抽屉；表格横向滚动 |
| `sm ~ lg` | 2 列卡片 | 单列 | 抽屉式侧栏 |
| `lg ~ xl` | 3 列卡片 | 两栏（主 2/3 + 侧 1/3） | 固定侧栏 |
| `≥ xl` | 4 列卡片 | 两栏 | 固定侧栏 + 更宽内容区 |

**管理台的最低支持宽度是 1280px**（SRS NFR-COMPAT-04）。窄屏可用但表格会横向滚动，这是可接受的取舍 —— 内网管理操作基本在桌面完成。

## 9. 性能

| 措施 | 说明 |
| --- | --- |
| 路由级代码分割 | 所有页面用 `React.lazy` + `Suspense`；管理台整体打成一个 chunk，普通用户不会下载到 |
| TanStack Query 缓存 | 门户列表 `staleTime: 60s`；工具详情 `staleTime: 5min`；`/meta` `staleTime: Infinity` |
| 查询键规范化 | `["tools", { q, category, tags, type, sort, page, pageSize }]`，保证同参数复用缓存 |
| 图片懒加载 | 卡片封面 `loading="lazy"` + `decoding="async"`；用固定 `aspect-ratio` 容器防布局抖动 |
| 缩略图 | 卡片与列表一律用 `?variant=thumb`（宽 480px），详情页才用原图 |
| 搜索防抖 | 输入 300ms 防抖后才更新 URL 并触发请求 |
| 虚拟滚动 | 仅在管理台表格超过 100 行时启用 `@tanstack/react-virtual`；门户分页 24 条不需要 |
| 首屏体积目标 | JS（gzip）< 500 KB。用 `rollup-plugin-visualizer` 在 CI 里监控，超阈值失败 |
| 预取 | 卡片 hover 时 `queryClient.prefetchQuery` 详情；移动端改为 `onTouchStart` |
| 构建产物 | `dist/assets/*` 带内容哈希 → nginx 设 `Cache-Control: immutable`；`index.html` 设 `no-cache` |

## 10. 明确不做的界面

| 不做 | 原因 |
| --- | --- |
| 数据可视化大屏、投屏轮播模式 | 你已确认门户是导航型（SRS 第 10 章） |
| 门户首页的推荐位轮播图 | 需要运营维护，且会挤占卡片墙空间 |
| 站内信 / 通知中心界面 | 无通知渠道需求，审批状态通过个人中心的状态标记传达 |
| 拖拽式仪表盘自定义 | 严重超出范围 |
| 富文本 WYSIWYG 编辑器 | Markdown 足够，且富文本会引入 XSS 风险面 |
| 多语言切换界面 | 仅简体中文 |
| 移动端 App / PWA 离线 | 内网桌面场景，不做 |
| 用户自助注册页面 | 管理员建号（SRS FR-AUTH-02） |
| 工具在线运行/预览的交互界面 | 平台只做归档分发，不执行（SRS 第 10 章 #1） |

## 11. 实现顺序建议

按依赖关系与可验证性排序，每一步都产出可点击的东西：

1. **设计令牌 + 布局骨架** —— `index.css`、`AppShell`、`TopNav`、主题切换、`Markdown`、`EmptyState` 等基础件
2. **登录 + 强制改密 + 鉴权封装** —— `api/client.ts`、`RequireAuth`、`RequireRole`
3. **门户首页** —— 先用 mock 数据把卡片墙、筛选、分页、URL 状态做出来（这是门面，值得先看到效果）
4. **工具详情页** —— 四种类型的差异化区块
5. **个人中心** —— 我的工具、工具编辑器、版本管理（表单最复杂，放在骨架稳定之后）
6. **审批队列** —— 复用详情页的渲染组件，加上审批动作
7. **其余管理页** —— 先做 `DataTable` 抽象，再逐页套用
8. **打磨** —— 骨架屏、空态、错误态、键盘快捷键、响应式、无障碍复查
