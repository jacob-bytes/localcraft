# 新手部署指南

**这份文档给谁**：第一次接触本项目、想把它跑起来的人。不需要读源码。

**本文的特别之处**：里面的每一条命令都在**全新克隆**上实际执行过，输出是真实的。
凡是本机做不到、没验证的，文中会明确标出「未验证」，不会含糊成「应该可以」。

---

## 0. 先决定你要哪一条路

| | 路径 A：本机试用 | 路径 B：生产部署 |
| --- | --- | --- |
| 目的 | 看看长什么样、点一遍功能 | 在内网服务器上长期跑 |
| 机器 | 你自己的电脑（macOS / Linux 都行） | openEuler 24.03 LTS，x86_64 或 aarch64 |
| 耗时 | 一条命令，几分钟 | 构建 + 传输 + 安装，约半小时 |
| 需要联网 | 需要（装依赖） | **不需要**，目标机可完全离线 |
| 命令 | `bash preview.sh` | `build-wheelhouse` → `make-release` → `install.sh` |

**不确定就先走路径 A。** 它跑的是与生产一致的拓扑（后端直接托管前端产物、单一 URL），
看到的界面和功能与生产没有区别。

## 路径 A：本机试用

### 前置

- Python **3.11+**（`python3.11 --version` 能跑就行）
- Node.js **18+**
- 能访问 PyPI 与 npm 源

### 一条命令

```bash
git clone https://github.com/jacob-bytes/localcraft.git
cd localcraft
bash preview.sh
```

`preview.sh` 会自己判断缺什么并补齐 —— 全新克隆跑下来是这样：

```
==> 创建后端虚拟环境（.../backend/.venv，使用 python3.11）
==> 安装后端依赖（requirements.lock，全量锁定）
==> 安装前端依赖（npm ci）
==> 构建前端产物
==> 初始化数据库（alembic upgrade head）
==> 播种演示数据（26 个工具 / 6 个账号）
  工具：26 个新建   file/skill 工具均已落盘真实占位包并写入 sha256
```

**不需要手动建 venv，也不需要先 `npm install`。**

### 打开与登录

浏览器打开终端里打印的地址（默认 <http://127.0.0.1:8000>），**不登录就能看门户**。

终端会直接列出全部演示账号：

| 角色 | 账号 | 密码 | 用途 |
| --- | --- | --- | --- |
| 超级管理员 | `admin` | `Admin@12345` | 全部页面 |
| 审批员 | `wangwu` | `Author@12345` | 预览审批台、验证角色边界 |
| 普通用户 | `zhangsan` / `lisi` | `Author@12345` | 上传与个人主页 |
| 只读访客 | `viewer` | `Viewer@12345` | 能看详情但下载被拒 |
| 需改密 | `newbie` | `Newbie@12345` | 登录后被强制跳转改密页 |

常用参数：

```bash
bash preview.sh --reset     # 丢弃预览数据重新来
PORT=8090 bash preview.sh   # 换端口
```

预览数据落在 `.preview/`（已 gitignore），**不碰** `backend/var/`，随便折腾。

### 本机试用会撞到的坑

**1. `npm ci` 报 `EPERM` / `TAR_ENTRY_ERROR`**

```
npm error code EPERM
npm error path /Users/you/.npm/_cacache/tmp/***
npm error Your cache folder contains root-owned files
```

原因是你的 npm 缓存目录**被 root 拥有**（历史上用过 `sudo npm`）。这不是项目问题。
两个办法：

```bash
# 办法一（推荐，一劳永逸）：把缓存目录改回自己
sudo chown -R "$(id -u):$(id -g)" ~/.npm

# 办法二（不改动你的机器）：把本次的缓存指到临时目录
npm_config_cache=/tmp/npmcache bash preview.sh
```

**2. pip 警告 `The directory '.../Caches/pip' ... is not writable`**

同上原因。pip 会**自动降级为不用缓存**，不影响结果，可以忽略。

## 路径 B：生产部署（openEuler）

分成两件事：**在一个联网的构建机上产出发布包**，然后**把包搬到目标机离线安装**。

> 构建机**不必是 openEuler**。它只负责下载 linux wheel（`pip download --platform`，
> 不安装），所以 macOS 和普通 Linux 都能干这活。已在 macOS 上实测。

### 第 0 步：目标机前置

| 项 | 要求 | 检查命令 |
| --- | --- | --- |
| OS | openEuler 24.03 LTS SP1~SP4 | `cat /etc/openEuler-release` |
| 架构 | `x86_64` 或 `aarch64` | `uname -m` |
| Python | `python3.11`（官方源自带） | `python3.11 --version` |
| 其他 | `sqlite3` `rsync` `tar` `openssl` `systemd` `curl` | `command -v sqlite3 rsync tar openssl systemctl curl` |

不确定就跑一遍自检，它会把缺什么一条条列出来：

```bash
# 直连部署（不用 nginx）
LOCALCRAFT_WEB_MODE=direct ./precheck.sh
# 或用 nginx 反代
./precheck.sh
```

### 第 1 步：构建机上产出发布包

```bash
cd web && npm ci && npm run build && cd ..   # 必须：make-release 需要 web/dist
bash scripts/build-wheelhouse.sh all          # 两套 wheel；也可写 x86_64 或 aarch64
bash scripts/make-release.sh 1.0.0
```

实测产物：

```
backend/dist/localcraft-1.0.0-offline-20260926.tar.gz    84M    390 个条目
backend/dist/localcraft-1.0.0/SHA256SUMS                         包内校验和
```

包里同时含 `wheelhouse-x86_64/` 与 `wheelhouse-aarch64/`（各 59 个 wheel、42 MB），
以及 `app/`、`migrations/`、`web/dist/`、`deploy/`、`scripts/`、`docs/`、`install.sh`。

**三个容易踩的点**：

1. **`build-wheelhouse.sh` 的参数是位置参数**。写 `--arch x86_64` 会直接报用法错误，
   正确的是 `bash scripts/build-wheelhouse.sh x86_64`。
2. **必须先构建前端**。跳过的话 `make-release.sh` 会明确报错：
   `[error] web/dist 不存在。请先在构建机执行 cd web && npm ci && npm run build`。
   报错本身很清楚，但别把它当成"脚本坏了"。
3. `make-release.sh` **必须带版本号**（`1.0.0`），不带会报用法。

可选的两条校验：

```bash
bash scripts/verify-wheelhouse.sh          # 校验每个 wheel 的平台标签
bash scripts/wheelhouse-arch-diff.sh       # 列出只出现在一边的包
```

### 第 2 步：把包传到目标机并安装

```bash
# 传输（示例）
scp backend/dist/localcraft-1.0.0-offline-20260926.tar.gz user@目标机:/tmp/

# 目标机上（root）
cd /tmp
tar xzf localcraft-1.0.0-offline-20260926.tar.gz
cd localcraft-1.0.0
sudo ./install.sh
```

**不要传 `LOCALCRAFT_WHEELHOUSE`。** `install.sh` 会按 `uname -m` 自己挑
`wheelhouse-x86_64` / `wheelhouse-aarch64`，并自动校验其中的 `MANIFEST.sha256`。

> 传一个**不存在**的路径会让它静默跳过离线路径、退化成**在线安装** ——
> 在离线机器上会报一个与真正原因无关的错。除非你确实要指向别处的 wheelhouse，
> 否则别加这个变量。

`install.sh` 的十步：

```
1/10 环境自检          2/10 校验发布包        3/10 创建系统用户与目录
4/10 建立代码软链      5/10 创建虚拟环境      6/10 安装依赖（离线 --no-index）
7/10 环境变量文件      8/10 数据库迁移        9/10 systemd / tmpfiles / logrotate
10/10 启动并健康检查
```

### 第 3 步：验证

```bash
systemctl is-active localcraft.service          # active
curl -sS http://127.0.0.1:8000/healthz          # {"status":"ok"}
curl -sS http://127.0.0.1:8000/readyz           # 200，含 database 与 storage 两项
curl -sS http://127.0.0.1:8000/api/v1/meta | jq .allow_anonymous_view   # true
```

`readyz` 返回 **503** 说明数据库或数据目录有问题 —— 它真的会去连库、去写文件，
不是只看端口通不通。

### 第 4 步：让外部能访问

**默认只能本机访问**（`LOCALCRAFT_HOST=127.0.0.1`）。二选一：

**方式 A：直连（不用 nginx，推荐入门）**

```bash
# /etc/localcraft/localcraft.env 改两处
LOCALCRAFT_WEB_MODE=direct
LOCALCRAFT_HOST=0.0.0.0

systemctl restart localcraft.service
firewall-cmd --add-port=8000/tcp --permanent && firewall-cmd --reload
```

之后从**另一台机器**访问 `http://<服务器IP>:8000`。

> 直连是**明文 HTTP**：登录密码在局域网内不加密。内网可信环境可以接受；
> 想加密又不想上 nginx，可以让 uvicorn 自己终结 TLS（见 docs/05 §5.13）。

**方式 B：nginx 反代（要 TLS / 限流时）**

```bash
install -m 0644 deploy/nginx/localcraft-http.conf /etc/nginx/conf.d/localcraft.conf
nginx -t && systemctl reload nginx
# 证书就绪后换成 deploy/nginx/localcraft-limits.conf + deploy/nginx/localcraft.conf
```

注意 `localcraft-http.conf` 与 `localcraft-limits.conf` **不能同时装**（同名 zone 会冲突）。

### 第 5 步：建管理员账号

安装脚本不会替你建账号。**第一次**用：

```bash
sudo -u localcraft bash -c '
  set -a; . /etc/localcraft/localcraft.env; set +a
  cd /opt/localcraft/app/current
  /opt/localcraft/venv/bin/python -m app.cli create-superadmin --username admin
'
```

密码走交互输入（**不要**用明文参数，会进 shell 历史）。新账号首次登录会被强制改密。

## 想在沙箱里先演练一遍安装？

不想拿真机冒险，可以用官方演练脚本。它会在 `backend/dist/drill` 里完整走一遍安装，
**不碰你的系统**：

```bash
cd web && npm ci && npm run build && cd ..
bash scripts/build-wheelhouse.sh x86_64
bash scripts/make-release.sh 1.0.0
bash scripts/m4-drill-install.sh
```

它做了两件聪明事（这也是为什么它能在 macOS 上跑通，而手动装不行）：

- **A 步**：用 `pip install --dry-run --no-index --platform ...` 证明**发布包里的
  linux wheelhouse 是完整的** —— 只看依赖解析，不真装，所以跨平台可行。
- **B 步**：为沙箱**另建一份本机架构的 wheelhouse**，因为 linux wheel 在 macOS 上装不了。

实测这套跑完的结论：

```
B）install.sh 十步全跑通，/readyz = 200（本机架构 wheel，离线 --no-index 路径）
A）linux wheelhouse 的离线可解性已证明（解析层）
✓ PIL  ✓ greenlet  ✓ pydantic_core  ✓ argon2  ✓ sqlalchemy  ✓ uvloop  ✓ aiosqlite
```

## 这份指南验证到什么程度

诚实比好看重要，所以把边界写清楚：

| 项 | 状态 |
| --- | --- |
| 全新克隆 → `bash preview.sh` → 可访问 | ✅ **实测**（macOS，392 文件的全新克隆） |
| `build-wheelhouse.sh` 双架构 | ✅ **实测**（macOS，各 59 wheel / 42 MB / 含 MANIFEST） |
| `make-release.sh` 产出发布包 | ✅ **实测**（84 MB / 390 条目 / 含 SHA256SUMS） |
| `install.sh` 十步 + 服务真的起来 | ✅ **实测**（沙箱 + 本机架构 wheel，`/readyz` 200） |
| 发布包内 **linux wheelhouse** 的离线可解性 | ✅ **实测**（依赖解析层，`--dry-run`） |
| **linux wheel 真的加载运行** | ❌ **未验证** —— 本机是 macOS，装不了 linux wheel |
| **在真实 openEuler 上安装** | ❌ **未验证** —— 无 openEuler 机器 |
| **aarch64 安装与运行** | ❌ **未验证** —— 无 aarch64 机器 |
| 真实 systemd 的 unit / slice / tmpfiles | ❌ **未验证** —— 本机无 systemd（演练走 `SKIP_SYSTEMD=1` 的 nohup 路径） |

也就是说：**脚本逻辑、命令、参数、产物形状都验证过了；目标 OS 与架构上的实际运行没有。**
到了 openEuler 上遇到问题，先看 [docs/08-运维手册](08-运维手册.md) 的故障排查章节。

## 出问题了看哪里

| 现象 | 先看 |
| --- | --- |
| 装依赖失败 / pip 报错 | `install.sh` 的输出；确认 wheelhouse 目录名与架构匹配 |
| 服务起不来 | `journalctl -u localcraft -n 100`；`curl /readyz` 看是哪一项失败 |
| 页面能开但接口 500 | `journalctl`；多半是数据库迁移没跑（`alembic upgrade head`） |
| 忘了管理员密码 | `/opt/localcraft/scripts/` 下的 CLI，或 docs/08 的对应条目 |
| 其他 | [docs/08-运维手册](08-运维手册.md)（现象 → 原因 → 怎么办） |
