# 00 · 关键决策记录

> 本文档记录项目立项阶段逐条确认的 34 项决策（D1–D34），是后续所有设计文档、
> 接口契约与实现的**上游依据**。当其它文档与本文档冲突时，以本文档为准；
> 例外是 `docs/09-勘误与已知限制.md`——它记录的是实现过程中对本文档的**修正**，
> 权威性高于本文档中已被明确勘误的条目。

这些决策来自需求澄清阶段的一问一答，**不是**事后补写的设计说明。
保留它们的目的是：让后来者知道"为什么是这样"，以及"哪些是明确不做的"。

## 决策表

| # | 决策项 | 结论 |
| --- | --- | --- |
| D1 | 工具形态 | 四种并存：**文件包**（zip/tar.gz/whl/exe）、**Agent Skill 包**（zip 内含 SKILL.md）、**在线网页工具**（内网 URL）、**Prompt 模板**（纯文本） |
| D2 | Skill 包预览深度 | 上传 zip 后服务端自动解压，提取 SKILL.md 渲染预览 + 展示包内文件树；文件树之外的普通文件不做在线预览 |
| D3 | 在线工具打开方式 | 新标签页直接跳转，不做 iframe 内嵌 |
| D4 | 分类体系 | 固定一级分类（管理员维护）+ 自由标签 tag（多对多），不做二级分类 |
| D5 | 可见性模型 | 三级：`public`（全员）/ `restricted`（指定用户或用户组）/ `private`（仅自己） |
| D6 | 用户组 | **需要**用户组管理，`restricted` 可见性可授权到组 |
| D7 | 版本号规则 | SemVer 字符串（如 `1.2.3`），用户手填，**不强制格式校验** |
| D8 | 历史版本保留 | 最多保留 **10 份历史版本**（不含当前版本），超出后淘汰最旧的非当前版本 |
| D9 | 门户形态 | 工具导航门户：搜索框 + 分类侧栏 + 工具卡片墙；**不做**数据可视化大屏与投屏轮播 |
| D10 | 统计需求 | 需要下载量 / 浏览量统计（用于门户热门排序）；不需要独立的管理员统计看板图表（仅提供数字概览） |

| D26 | 管理 API 鉴权 | 只做**长效 API Token**（可签发/吊销/设权限范围）；**不做** OAuth2 client_credentials |

| D28 | 存储配额 | 需要配额限制（单文件 / 单用户 / 平台总量），默认值见 SRS 第 8 章 |

| D31 | 离线 wheel 来源 | 有可联网的构建机，且能安装**与目标机同版本的 openEuler**。因此两套 wheelhouse 均可在真实目标 OS 上产出与验证，无需处理跨发行版 glibc 兼容问题 |

| D34 | 开发环境 | 本机开发用 **Python 3.13**，但代码目标语法为 **3.11**。必须加静态守卫（见下方「Python 版本策略」） |

## v1.0.0 之后的追加决策（D35 起）

v1.0.0 交付后，在讨论「优化与新增功能」时又确认了以下几条。
**D9 与 D10 被重新提出过，结论是维持不变** —— 记录在此以免再次反复。

| # | 决策项 | 结论 |
| --- | --- | --- |
| D35 | 总览大屏（**重新提出**） | **维持 D9 / D10，不推翻**。不做图表、不做投屏；把**纯数字概览做强**（30 日趋势、活跃贡献者、分类分布）。Top 下载榜原本就已存在 |
| D36 | 「预估效率提升 / 节省人力」数字来源 | **工具作者在发布时自填**「单次使用预计节省分钟数」。平台只做聚合，**必须标注为估算**，并展示填写覆盖率。**严禁**由平台凭空推算 |
| D37 | 工具评价形式 | **只做点赞**（每人每工具至多一票、可取消、整数计数）。**不做 1~5 平均分** —— 百人小团队里平均分会产生 `4.7` 这类假装精确的数字，且易变人情分 |
| D38 | 上传去重的实现位置 | **服务端**。浏览器算 SHA-256 需要 `crypto.subtle`，它只在安全上下文（HTTPS / localhost）可用；而本项目按 D39 用 `http://<ip>:<port>` 直连，该 API 不可用，且 Web Crypto 没有可接受的回退 |
| D39 | 访问方式 | **默认 `http://<ip>:<port>` 直连**，不强制 nginx 反代。nginx/TLS 作为可选项保留（`deploy/nginx-*.conf`） |
| D40 | 预览图 / 占位块的配色 | **统一为中性浅色**（米白 / 浅灰），**不要五颜六色**。用语义令牌（`bg-muted`）实现，深浅主题各自自适应（深色下是深中性，不是白色）。**类型徽标（文件包 / 在线工具 / Skill）保持彩色** —— 它是功能性小标签、有信息量，不属于「预览图片」。用户**真实上传**的封面一律不动。见契约 §34 |
| D41 | 详情页「没有图」时的图区 | **完全收起** —— 不渲染外壳、不留空盒子、不加间距补偿，标题自然上移。两种情形都收起：① 后端没下发任何图；② **每一张**图都加载失败。★ **必须区分「加载中」与「加载失败」**，不能在加载过程中先收起再冒出来。★ **范围限定：只作用于详情页图廊**；门户卡片 / 我的工具 / 回收站的缩略图盒子**照旧显示占位**（卡片墙需要每格一个一致的盒子）。见契约 §35 |
| D42 | 种子演示封面的观感 | 浅中性底 + **一点淡淡的几何标记**（圆角矩形轮廓 + 内切圆），让它读起来像「一张图」而不是一块没加载出来的灰；标记**只能是比底色暗一两档的中性色**（各通道同减，不引入色相），不画文字、不加载图标字体。**全尺寸提到 1280×720**（原 320×180 被详情页拉伸近 4 倍会糊），**缩略图仍 160×90**。见契约 §34 / §35 |

> **D36 与 D37 是同一类问题的两种处理**：宁可少给一个数字，也不给一个
> 看起来精确、实际无从验证的数字。这类数字一旦进入汇报口径就再也纠不回来了。

## 明确不做的事（易被反复提出，集中列出）

| 不做 | 依据 | 说明 |
| --- | --- | --- |
| 数据可视化大屏、投屏轮播 | D9，D35 再次确认 | 门户形态是「搜索框 + 分类侧栏 + 卡片墙」 |
| 独立的管理员统计看板图表 | D10，D35 再次确认 | 仅提供数字概览，不做图表 |
| 工具星级平均分 | D37 | 只做整数点赞数 |
| 平台自行推算「节省人力」 | D36 | 只能来自作者自填，且必须标注估算 |
| iframe 内嵌在线工具 | D3 | 新标签页直接跳转 |
| 容器化交付 | D22 | systemd 原生，**禁止** Docker |
| 全量审计日志 | D16 | 仅保留必要的操作记录 |
| 单架构交付 | D23 | x86_64 与 aarch64 **都**必须支持 |
| 给无封面的工具在详情页补一张默认图 / 占位块 | D41 | 直接**收起**图区，不留空盒子；占位只保留在卡片墙 |
| 预览图按分类 / 按类型上色（彩色渐变） | D40 | 统一中性色；彩色只留在类型徽标上 |
