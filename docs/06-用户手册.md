# 用户手册

**适用平台**：localcraft — 内网工具 / Skill 共享平台

**适用对象**：平台全体使用人员（普通用户、只读访客）

---

## 0. 这本手册给谁看、怎么用

这本手册写给**不参与平台开发**的同事。不需要看代码、不需要懂技术，按步骤操作即可。

- 第 1 章讲**登录和密码**，第一次使用务必先看。
- 第 2~4 章讲**怎么找工具、怎么下载**，最常用。
- 第 5~7 章讲**怎么上传自己的工具**，以及提交审批后会发生什么。
- 第 8 章讲**个人中心**；第 9 章是**常见问题**（「现象 → 原因 → 怎么办」），报错先查这里。

阅读约定：

| 写法 | 含义 |
| --- | --- |
| **页面 → 区域 → 按钮** | 按界面文字逐层找，例如「首页 → 左侧筛选栏 → 分类」 |
| `等宽字体` | 界面上的按钮名、字段名、错误码，或需要照抄的内容 |
| 平台地址 | 由管理员提供，本手册统一写作「平台地址」 |

> 本手册只描述平台**当前真实存在**的功能。界面文字以你实际看到的为准；手册没写到的内容，请以界面为准并反馈给管理员。

## 1. 登录与改密

### 1.1 登录

1. 用浏览器（推荐 Chrome / Edge）打开管理员给你的**平台地址**。
2. 在登录页填写 `用户名`（管理员分配，大小写不敏感）与 `密码`（管理员给的初始密码）。
3. 点 `登录`。

平台**没有自助注册入口**。账号只能由超级管理员创建或批量导入；忘记用户名请联系管理员。

### 1.2 首次登录必须改密

新账号、以及被管理员**重置过密码**的账号都带强制标记：登录后不会进入首页，而是直接跳到 `修改密码` 页。在改密完成前，除「查看当前登录信息」和「修改密码」本身外，**任何业务操作都会被拒绝**，返回 `403 PASSWORD_CHANGE_REQUIRED`（提示「请先修改初始密码」）。这是刻意的设计——初始密码是管理员传达的，必须由本人换成只有自己知道的密码。

改密步骤：按 1.3 节规则填写 `初始密码`（主动改密时该字段叫 `原密码`）、`新密码`、`确认新密码`，点 `确认修改`。强制模式下页面没有「跳过」按钮，顶栏导航也会隐藏。

改密成功后会提示「密码已更新，请重新登录」，并**清除当前登录状态**（需用新密码重新登录），同时**吊销你在其他浏览器/设备上的全部会话**。

### 1.3 口令要求（服务端真实规则）

新密码必须**同时**满足三条，缺一条都会被拒（`400 VALIDATION_ERROR`，错误信息会逐条列出原因）：

| 规则 | 说明 |
| --- | --- |
| 长度 | **不少于 10 位** |
| 字符类别 | 大写字母、小写字母、数字、符号 四类中**至少 3 类** |
| 不得与用户名相同 | 比较时忽略大小写与全角/半角差异 |

另外，**新密码不能与当前密码相同**。改密页有实时强度提示，但服务端才是权威。

### 1.4 连续输错密码会锁定账号

连续失败 **5 次**锁定账号 **15 分钟**（两项均可由管理员调整）。

- 第 1~5 次输错都提示「用户名或密码错误」（`401 INVALID_CREDENTIALS`）。**用户名不存在时也是同一句提示**，避免有人靠提示语试探哪些用户名存在。
- 第 5 次失败时账号被锁定，**下一次**登录才会收到 `423 ACCOUNT_LOCKED`（「账号已锁定，请 N 分钟后重试」），登录页显示剩余时间。锁定期内**即使密码正确也拒绝**。
- 登录成功一次，失败计数立刻清零；锁定期自然结束后计数也清零，重新获得 5 次机会。

### 1.5 账号被禁用

登录返回 `403 ACCOUNT_DISABLED`（「账号已禁用，请联系管理员」）；已打开的会话也会失效。

### 1.6 退出登录

点右上角**头像 → 退出登录**。退出会在服务端立即吊销本次登录凭证，不是只清浏览器缓存。

## 2. 找工具（门户首页）

登录后默认进入 `首页`。页面结构：顶栏（搜索框 / 主题切换 / 头像菜单）+ 内容区（左侧筛选栏 + 右侧工具卡片墙）。

### 2.1 搜索

- 顶部搜索框输入关键词即自动搜索（有短暂延迟，属正常现象）。
- 快捷键 `⌘K`（macOS）或 `Ctrl+K`（Windows）唤起搜索面板，可直接跳转到某个工具。
- 搜索范围：**工具名称、简介、详情正文、标签名**。

### 2.2 筛选

左侧筛选栏（窗口较窄时折叠为顶部 `筛选` 按钮）提供三组筛选，可叠加：

| 区块 | 交互 | 说明 |
| --- | --- | --- |
| 分类 | 单选，每项带该分类下**你能看到的**工具数量 | 点「全部」取消分类筛选 |
| 类型 | 多选 | `文件包` / `在线工具` / `Skill` / `提示词` |
| 标签 | 点击标签快速切换，可展开更多 | 数量多时只显示前若干个 |

已选条件显示为带 `×` 的标签，点 `清除全部` 一次取消。筛选、排序、页码都会写进浏览器地址栏，因此**链接可直接分享、刷新不丢状态**。

> 门户界面目前**没有**「按作者筛选」与「按状态筛选」入口。按作者筛选只在接口层面支持（`owner` 参数，填用户名）。门户只展示已发布工具，按状态查看自己的工具请用「我的工具」页。

### 2.3 排序、分页与视图

- 排序下拉框：`热门`（默认，按下载量）、`最新发布`、`名称`。
- 每页条数：`每页 12` / `每页 24`（默认） / `每页 48`；翻页控件在列表底部。请求超出总页数时显示空列表，属正常现象。
- 排序框右侧的纯图标按钮可在**卡片视图**与**列表视图**间切换；列表视图每行显示名称、类型、分类、下载量、更新时间，适合快速扫读。选择会记住。

### 2.4 只读访客（viewer）能看到什么

| 能力 | 只读访客 |
| --- | --- |
| 登录、浏览门户、搜索、看公开工具详情 | ✅ 可以 |
| 下载工具（包括公开工具） | ❌ 不可以，按钮置灰并提示「当前角色无下载权限」 |
| 创建 / 编辑 / 提交自己的工具 | ❌ 不可以 |

只读访客也看不到「指定可见」与「私有」工具。打开无权页面通常直接显示 404——平台对「不存在」和「无权查看」统一返回 404，以避免泄露资源是否存在。

## 3. 四种工具类型各自怎么用

| 类型代码 | 界面名称 | 交付内容 | 详情页做什么 |
| --- | --- | --- | --- |
| `file` | 文件包 | 一个交付文件（压缩包、安装包等） | 看文件信息，点 `立即下载` |
| `webapp` | 在线工具 | 一个内网网址 | 点 `打开工具` 在新标签页打开 |
| `skill` | Skill | 一个含 `SKILL.md` 的 zip 包 | 三页签预览：`SKILL.md` / `包内文件` / `元信息` |
| `prompt` | 提示词 | 一段提示词正文（Markdown） | 查看正文，点 `复制提示词` |

**`文件包`**：内容区显示文件名、大小、格式、SHA256。若是 `.exe` / `.sh` / `.ps1` 等可执行文件，会额外显示风险提示。平台**只做归档分发，绝不在服务器上执行任何上传文件**。

**`在线工具`**：内容区有 `打开工具` 按钮，在新标签页打开地址，地址文本旁有 `复制工具地址`。平台**不预先探测网址是否可达**，「打不开」通常是工具本身的问题，请联系作者。编辑页的 `健康检查 URL` 当前**不产生任何效果**（平台尚未启用探活）。

**`Skill`**：三个页签默认停在 `元信息`；`SKILL.md` 与 `包内文件` 两个页签**切过去时才请求**，首屏不会加载大内容。有两点要知道：

1. 文件树**只有 `SKILL.md` 能看内容**（切到 `SKILL.md` 页签）；其他文件只显示路径与大小，界面写明「仅 SKILL.md 支持预览」。
2. 文件树**最多保存 2000 条**。超过时底部出现黄色提示「包内文件过多，仅显示前 2000 项」。这只是**展示截断，不影响工具使用与下载**；超过 5000 个文件的上传包会被直接拒绝。

**`提示词`**：内容区以等宽字体展示正文，右上角 `复制提示词` 按钮，旁边显示字符数；正文较长时可展开/收起。

## 4. 下载

### 4.1 下载怎么发生（下载票据）

平台的下载是「**先申请临时票据，再用票据下载**」：点 `立即下载`（或版本历史里的 `下载`）后，平台签发一张**有效期 60 秒**的票据，票据绑定了「这个工具 + 这个版本 + 你本人」，浏览器随即用票据开始下载。

- 票据 **60 秒后自动失效**。若弹出下载后你取消了、或浏览器很久之后才真正发起请求，会下载失败（返回 404）——**重新点一次 `立即下载` 即可**。
- 票据**绑定你本人**，复制给别人也用不了。
- 票据在有效期内可重复使用（断点续传会发多次请求），因此大文件中途短暂中断后可以继续。

### 4.2 下载计数与下载日志

- 每次成功下载都计入该工具的**下载量**（卡片、详情页可见），并影响「热门」排序。
- 每次下载都会记录**工具、版本、时间**，可在 `个人中心 → 我的下载` 回看，点名称回到详情页。
- 下载明细默认保留 **180 天**，超期由系统清理。

### 4.3 下载历史版本

详情页下方 `版本历史` 列出所有可下载版本：标注 `当前` 的是默认下载版本；标注 `历史` 的**仍可下载**；标注 `已归档` 的**不可下载**（按钮禁用，因为平台只保留最近若干份历史版本的文件）；标注 `待审` 的版本只有**作者本人和审批管理员**可见。

### 4.4 核对下载是否完整（SHA256）

详情页给出文件的 SHA256（版本列表里显示前 16 位，完整值在文件信息区，旁边有 `复制 SHA256`）。用它可在本地核对文件是否损坏或被篡改。

**把命令里的 `~/Downloads/package.zip` 换成你实际下载的文件路径，在你自己电脑上执行。**

macOS（「终端」）：

```bash
shasum -a 256 ~/Downloads/package.zip
```

Linux（「终端」）：

```bash
sha256sum ~/Downloads/package.zip
```

Windows（PowerShell）：

```powershell
Get-FileHash -Algorithm SHA256 "$HOME\Downloads\package.zip"
```

把输出与页面上的 SHA256 对比，**完全一致**即文件完好；大小写不影响对比结果。

## 5. 上传自己的工具

> 只读访客没有上传权限；普通用户、审批管理员、超级管理员可以上传。

### 5.1 入口与必填字段

入口：`我的工具` 页 → 新建入口（地址形如 `/me/tools/new`）。表单分五块：**基本信息 / 工具类型 / 详情说明 / 截图 / 可见性**。

| 字段 | 要求 |
| --- | --- |
| `工具名称` * | 1~128 字符，允许重名 |
| `简介` * | 1~500 字符，显示在门户卡片上 |
| `分类` * | 从管理员维护的分类中选择 |
| `详情说明` * | Markdown 正文，有 `编辑` / `预览` 页签，最多 10 万字符 |
| `标签` | 选填，**最多 8 个**，单个 ≤ 64 字符；可输入新标签 |
| `截图` | 选填，**最多 8 张**，第 1 张自动作封面、可拖拽排序。单张 ≤ 5 MB，支持 PNG / JPG / WEBP / GIF（按**真实图片格式**判断，改扩展名无效） |

工具的访问链接由系统按名称自动生成（中文名会回退成 `tool-短哈希`），无需操心，也不可手改。

### 5.2 各类型的额外要求

| 类型 | 额外要求 |
| --- | --- |
| `文件包` | 必须上传交付文件，**单文件默认上限 200 MB** |
| `在线工具` | 必须填 `工具 URL *`，且以 `http://` 或 `https://` 开头；`健康检查 URL` 选填（当前不生效） |
| `Skill` | 必须上传 zip 包，包**根目录或单层子目录**下要有 `SKILL.md` |
| `提示词` | 必须填写提示词正文（在类型专属区直接输入） |

**允许上传的扩展名（默认清单）**：

```text
zip  tar.gz  tgz  whl  tar  gz  7z  rar
exe  msi  deb  rpm  sh  py  md  txt
json  yaml  pdf  png  jpg
```

不在清单内的扩展名会被拒绝（`415 UNSUPPORTED_MEDIA_TYPE`）。该清单由管理员在系统设置中维护，可能与上面不同。

**Skill 包上传的硬性限制**（平台安全校验强制）：包内文件数 ≤ 5000；解压后总体积 ≤ 1 GB；单个文件解压后 ≤ 200 MB；层级深度 ≤ 16；压缩比 ≤ 200 倍；解压耗时 ≤ 60 秒。包内**不允许**出现绝对路径、`..` 路径段、空字节或符号链接条目，出现即整包拒绝。

### 5.3 可见性三级

在表单 `可见性` 区块选择，三级的准确含义：

| 取值 | 界面名称 | 谁能看到、谁能下载 |
| --- | --- | --- |
| `public` | `公开` | 所有已登录用户可见、可下载（只读访客可见但不可下载） |
| `restricted` | `指定可见` | 只有你与**授权名单**里的用户/用户组可见、可下载；**必须至少配置一条授权**，否则改不进去 |
| `private` | `私有` | 只有你自己可见（超级管理员在平台开启「可见他人私有工具」时也能看到） |

补充：**作者永远能看到自己的工具**，无论选了哪一级；三种可见性**随时可改**（已发布状态下也可），改动立即生效、**不需要重新审批**；从 `指定可见` 切到 `公开`/`私有` 时，原授权名单**不会删除**，只是暂不生效，切回来还在。

### 5.4 授权给用户或用户组（「指定可见」）

选中 `指定可见` 后展开授权区：选择 `主体类型`（`用户` / `用户组`）→ 在 `主体 ID` 填对方的**数字 ID** → 点 `添加` → 保存。保存成功后列表会显示服务端回填的名称（如 `张三`、`运维组`）。每条授权右侧有「允许下载」勾选框，也可逐条删除。

需要注意：

- **界面上没有「搜索成员」功能**，只能填数字 ID（页面提示「暂无可用的成员检索接口，请填写用户 / 用户组 ID；保存后由服务端回填名称」）。**不知道对方 ID 时请找超级管理员查询。**
- 授权条目**最多 100 条**；不能授权给自己（`400 SELF_GRANT`）；同一主体不能重复（`400 DUPLICATE_ENTRY`）；用户/用户组必须存在且处于启用状态（`400 SUBJECT_NOT_FOUND`）。
- 授权列表是**整体替换**：保存时提交的是界面上的完整列表；一条都没有时保存为「指定可见」会报 `400 ACL_REQUIRED`。

### 5.5 上传版本并提交审批

工具本身只是「壳」，交付内容放在**版本**里。完整流程：

1. 填好元信息（5.1 节），点 `保存草稿`，状态为 `草稿`。编辑页每 30 秒或字段失焦会自动保存一次。
2. 在类型专属区上传**版本内容**：`文件包`/`Skill` 拖入文件，`在线工具` 填 URL，`提示词` 填正文。
3. 填写 `版本号 *`（1~64 字符，**同一工具内不可重复**）与 `变更说明`（建议填写，留空时界面会二次确认）。
4. 点 `提交审批`。若工具还没有任何版本内容，会被拒（`409 STATE_CONFLICT`，「该工具还没有可提交的版本，请先上传内容」）。若是 Skill 包解析失败（如缺 `SKILL.md`、`SKILL.md` 头部 YAML 写错），**允许存草稿但不允许提交**（`422 SKILL_PARSE_FAILED`），修正压缩包后重新上传再提交。

版本上传对话框里也有 `上传后立即提交审批` 开关，打开即上传即提交。

**提交后**：新工具进入 `待审批`，**不出现在门户**；已发布工具发新版本进入 `有新版本待审`，**门户仍显示旧版本、别人下载到的也仍是旧版本**，完全不受影响。若平台开启「全部自动放行」或你在免审白名单中，提交后**立即发布**。

状态含义：`草稿`（未提交，门户不可见）、`待审批`（首次提交，门户不可见）、`已发布`（门户可见）、`有新版本待审`（门户可见，展示当前版本）、`已驳回`（门户不可见）、`已下架`（门户不可见）。注意页签有重叠：一个「有新版本待审」的工具会同时出现在 `待审` 和 `已发布` 两个页签。

**能不能改**：`草稿`、`已驳回`、`已发布`、`有新版本待审`、`已下架` 状态下元信息（名称/简介/详情/可见性/标签）都能改，改了**不触发重新审批**；`待审批`（首次提交）状态下不能改任何内容（`409 TOOL_NOT_EDITABLE`，「待审状态下不可编辑，请先撤回提交」），请先点 `撤回提交`。

## 6. 发新版本

入口：`我的工具` → 某个工具的 `版本管理`（地址形如 `/me/tools/{id}/versions`），或 `上传新版本` 按钮。

**版本号**：手工填写，1~64 字符；平台**不做格式强校验**，建议用语义化版本（如 `1.2.0`）；**同一工具内不能重复**，重复返回 `409 VERSION_EXISTS`。

**变更说明**：Markdown，建议填写（留空上传时界面会二次确认）。可以事后修改，但**只有 `待审` 或 `已驳回` 的版本可以改**；已通过审批的版本，内容与变更说明都不能再改，只能发新版本（`409 STATE_CONFLICT`）。

**历史版本保留数量**：默认保留 **10 份**（不含当前版本，管理员可配，范围 1~50）。超出后最旧的历史版本被标记为 `已归档`——数据库记录保留（版本号、变更说明、大小仍在列表中可见），但**磁盘文件被物理删除，因此不可再下载**。版本管理页会提示「历史版本保留 10 份，当前 N 份」。

**删除版本**：`待审` 与 `已驳回` 的版本可删除；**当前版本不能删除**，要停用已发布工具请走「下架」流程（联系审批管理员）。删除「已发布工具的待审新版本」后，工具会自动退回 `已发布`。

**如何回滚 / 切换当前版本**：**平台当前没有「一键回滚」或「把某个历史版本设为当前版本」的功能**，界面上也没有这样的按钮。可以做到的是：下载仍在保留期内的历史版本；若确实要让旧内容重新上线，需**上传一个内容相同、版本号不同的新版本**，走正常审批流程；只想临时撤下，请联系审批管理员执行「下架」。

> 「有新版本待审」时**不能**用「撤回提交」取消——撤回只支持首次提交的 `待审批` 状态。要取消待审版本，请到 `版本管理` **删除该待审版本**，工具会自动回到 `已发布`。

## 7. 审批结果

审批由审批管理员或超级管理员操作。**平台不会发邮件、站内信或即时消息**，结果需自己到 `我的工具` 页查看。

**通过**：首次提交通过后工具变为 `已发布`，按可见性出现在门户；新版本通过后成为 `当前版本`，原当前版本自动转为 `历史`；若原版本因超出保留上限被淘汰，会显示为 `已归档`。

**驳回**：驳回**必须填写理由**（5~2000 字），理由原文展示给你。**在哪里看**：① `我的工具` 页中状态为 `已驳回` 的那条下方会展开红色提示，标题「审批未通过」，正文即驳回理由；② `版本管理` 页被驳回版本的时间线旁，右侧详情面板有「驳回理由」区块。

**被驳回后怎么改、怎么再提交**：在红色提示里点 `修改后重新提交`（直接打开编辑页）→ 按理由修改（若要改交付文件/URL/提示词正文，需**上传一个新版本号**，已过审与被驳回的版本内容都不能就地替换）→ 重新点 `提交审批`。

一个**重要区别**：被驳回的是**新工具的首次提交** → 工具变为 `已驳回`，门户看不到；被驳回的是**已发布工具的新版本** → 只有那个新版本被驳回，**工具本身退回「已发布」，当前版本完全不变**，门户一切照旧。

**下架与重新上架**：审批管理员可下架已发布工具，下架**必须填理由**；下架后工具立即从门户消失，你在 `我的工具` 页会看到 `已下架` 状态与**下架理由**；下架时若正好有新版本排队，该待审版本会被一并取消。重新上架由审批管理员操作，理由选填——**作者本人不能自行重新上架**。

**审批被别人抢先处理**：两个管理员同时处理同一条时，后提交者收到 `409 ALREADY_PROCESSED`（「该条目已被处理，请刷新列表」）。这是正常的并发保护，刷新页面即可。

入口：右上角**头像 → 个人中心 / 我的工具**。

### 8.1 `个人中心`（`/me`）

| 区块 | 内容 |
| --- | --- |
| 账号信息 | 头像、显示名、用户名、邮箱、角色徽标。可改**显示名**和**邮箱**；**用户名创建后不可修改** |
| 存储用量 | 进度条显示「已用 / 配额」，并显示平台整体用量。默认单用户 2 GB、平台总量 50 GB（管理员可调） |
| 统计 | 我的工具数、我的版本数、已发布数量、累计下载量 |
| 我的下载 | 最近下载过的工具与版本，可翻页，点名称回到详情页 |
| 修改密码 | 入口跳转到改密页 |

### 8.2 `我的工具`（`/me/tools`）

顶部按状态分页签：`全部` / `草稿` / `待审` / `已发布` / `已驳回` / `已下架`。每行显示工具名与类型、状态、版本、可见性、下载量/浏览量、更新时间。右侧操作菜单：`编辑`、`版本管理`、`提交审批`（草稿/已驳回时出现）、`撤回提交`（待审时出现）、`查看详情`、`删除`。被驳回的行下方有红色提示与 `修改后重新提交`；已下架的行下方有下架理由。

删除是**软删除**：工具立刻从所有列表消失，但数据仍保留，超级管理员可在管理后台的回收站查看或彻底清除。**普通用户无法自行恢复已删除的工具**，误删请联系管理员。

### 8.3 API Token：普通用户不能自己签发

**普通用户（包括审批管理员）不能自己签发 API Token。** 签发、查看、吊销 Token 只对**超级管理员**开放（管理后台 → `API Token` 页）。

需要用脚本调用平台接口时，请联系超级管理员代签，并告知用途与所需权限范围（Scope）。Token 明文**只在签发时显示一次**，请立即保存。

## 9. 常见问题（FAQ）

每条按「现象 → 原因 → 怎么办」写；括号里是接口返回的 HTTP 状态与错误码，界面通常只显示中文提示。

### Q1. 登录提示「用户名或密码错误」

- **现象**：无法登录（`401 INVALID_CREDENTIALS`）。
- **原因**：密码错误或用户名不存在；平台对两种情况**故意使用同一句提示**，防止试探用户名。
- **怎么办**：确认大小写与输入法（别在中文输入法下输密码）。仍失败请让管理员核实用户名或重置密码；重置后需重新走「首次登录改密」。

### Q2. 登录提示「账号已锁定，请 N 分钟后重试」

- **现象**：登录按钮不可用，页面显示倒计时（`423 ACCOUNT_LOCKED`）。
- **原因**：连续输错密码达到阈值（默认 **5 次**），锁定时长默认 **15 分钟**；锁定期内密码正确也拒绝。
- **怎么办**：等倒计时结束再登录（期满后失败计数自动清零）。急着用可联系管理员。**不要反复重试**，那不会缩短锁定时间。

### Q3. 登录后立刻被跳到改密页 / 新密码总被拒

- **现象**：登录后进入 `修改密码` 页且无「跳过」；或改密报 `400 VALIDATION_ERROR`。
- **原因**：账号带「必须修改初始密码」标记；或新密码不满足「长度 ≥ 10 位、四类字符至少 3 类、不得与用户名相同」，或与当前密码相同。
- **怎么办**：按 1.3 节设置新密码后提交，成功需用新密码重新登录。若见到 `403 PASSWORD_CHANGE_REQUIRED`，说明改密尚未完成。

### Q4. 上传文件提示「文件过大」

- **现象**：`413 PAYLOAD_TOO_LARGE`。
- **原因**：单文件超过上限，**默认 200 MB**（管理员可调，范围 1~2048 MB）。
- **怎么办**：压缩或拆分文件，或联系管理员调整上限。大小按**压缩包文件本身**计算，不是解压后大小。

### Q5. 上传提示「不支持的文件类型」

- **现象**：`415 UNSUPPORTED_MEDIA_TYPE`，错误详情列出允许的扩展名。
- **原因**：扩展名不在白名单内。默认清单见 5.2 节——例如 `.csv`、`.xlsx`、`.docx`、`.svg`、`.iso`、`.go` **都不在默认清单内**。
- **怎么办**：把内容打成 `.zip` 上传，或联系管理员把该扩展名加入白名单。

### Q6. 上传 zip 被拒

- **现象**：`ZIP_INVALID`（「不是合法的 zip 文件」/「条目 X 数据损坏」）、`ZIP_PATH_TRAVERSAL`（含非法路径）、`ZIP_BOMB_DETECTED`（解压后体积/压缩比/耗时超限）、`ZIP_TOO_MANY_FILES`（文件数超限，上限 5000）之一。
- **原因**：文件损坏、把 rar/7z 改名成 `.zip`（平台按真实内容判断）；或触发 5.2 节的安全校验（非法路径条目、总体积 > 1 GB、单文件 > 200 MB、压缩比 > 200 倍、解压 > 60 秒、文件数 > 5000）。
- **怎么办**：重新打成真正的 zip；清理非法条目；减小包体（拆分内容、移除无用大文件与构建产物）。错误详情会指出具体条目或超限项。

### Q7. Skill 包上传提示「未找到 SKILL.md」

- **现象**：`422 SKILL_MD_NOT_FOUND`，提示搜索过的位置。
- **原因**：平台只认**压缩包根目录**或**单层子目录**下的 `SKILL.md`（如 `SKILL.md` 或 `my-skill/SKILL.md`）。你的包可能是 `a/b/SKILL.md`（两层）或文件名大小写不一致。
- **怎么办**：调整结构，让 `SKILL.md` 位于根目录或只隔一层文件夹。

### Q8. 提示「Skill 包解析失败」，不能提交审批

- **现象**：可保存草稿，但 `提交审批` 被拒（`422 SKILL_PARSE_FAILED`）。
- **原因**：`SKILL.md` 存在，但头部 YAML frontmatter 语法有问题或不是键值对结构；平台视其为非致命警告——允许存草稿，**不允许提交审批**。
- **怎么办**：查看页面上的解析错误详情，修正 `SKILL.md` 头部 YAML，**重新上传一个新版本**再提交（草稿不会自动修复）。

### Q9. 点「提交审批」没反应 / 提示不能编辑

- **现象**：状态为 `待审批` 时改内容或再上传版本被拒（元信息报 `409 TOOL_NOT_EDITABLE`，上传版本报 `409 STATE_CONFLICT`）。
- **原因**：首次提交进入待审后，平台会冻结内容，避免审批人审的内容与最终发布的不一致。
- **怎么办**：在 `我的工具` 页对该工具点 `撤回提交`（回到 `草稿`），改完再提交。

### Q10. 版本号重复

- **现象**：`409 VERSION_EXISTS`（「版本 X 已存在」）。
- **原因**：同一工具内版本号必须唯一；旧版本即使已被驳回或归档，版本号仍被占用。
- **怎么办**：换一个版本号（如 `1.2.0` → `1.2.1`），或在 `版本管理` 里删除未过审的旧版本后重试。

### Q11. 明明有权限却看不到某个工具，或打开就是 404

- **现象**：门户列表中没有；用别人发来的链接打开显示 404。
- **原因**：平台对「不存在」与「无权查看」统一返回 `404 NOT_FOUND`。常见原因：工具是 `私有` 而你不是作者；工具是 `指定可见` 而你不在授权名单/授权用户组；工具尚未审批通过（`草稿`/`待审批`/`已驳回`）；工具已被下架；你被移出了某个用户组。
- **怎么办**：联系工具作者把你的账号加入授权（需要你的用户 ID，可让管理员提供），或改用 `公开`。**权限每次请求实时判定**——管理员把你加入用户组后刷新页面即生效，无需重新登录。

### Q12. 只读访客看不到下载按钮

- **现象**：能看详情，但下载按钮置灰，提示「当前角色无下载权限」。
- **原因**：`只读访客` 角色的定义就是「可浏览、不可下载」，公开工具也一样。
- **怎么办**：需要下载请让管理员把你的角色调整为 `普通用户`。

### Q13. 设置「指定可见」时报错

- **现象**：`400 ACL_REQUIRED`（一条授权都没有）、`400 SELF_GRANT`（把自己加进了名单，作者天然可见）、`400 DUPLICATE_ENTRY`（同一主体加两次）、`400 SUBJECT_NOT_FOUND`（用户/用户组 ID 不存在或已禁用）之一。
- **原因**：见括注。
- **怎么办**：按提示处理。**不知道对方 ID 时请找超级管理员查询**（界面上没有成员搜索功能）。

### Q14. 上传提示配额不足

- **现象**：`507 USER_QUOTA_EXCEEDED`（个人配额）或 `507 INSUFFICIENT_STORAGE`（平台总配额），详情带已用与上限 MB 数。
- **原因**：默认单用户 2 GB、平台总计 50 GB，超出即拒绝新上传。
- **怎么办**：在 `个人中心` 看用量，删除不再需要的工具或历史版本释放空间；平台总量满则联系管理员扩容或清理。

### Q15. 下载失败 / 点了没反应

- **现象**：点 `立即下载` 后浏览器没开始下载，或之前弹出过下载但最终失败（404）。
- **原因**：下载票据**只有 60 秒有效期**；取消后隔太久重试、或在另一台设备打开同一链接都会失效。票据还与你的账号绑定，转发给他人无法使用。
- **怎么办**：回详情页**重新点一次 `立即下载`**。仍失败则确认该版本不是 `已归档`，并确认你的角色有下载权限（见 Q12）。

### Q16. Skill 的文件列表不完整

- **现象**：`包内文件` 页签底部提示「包内文件过多，仅显示前 2000 项」。
- **原因**：文件树最多保存 **2000** 条，超出即截断展示。
- **怎么办**：**不影响下载与使用**，点 `立即下载` 拿到的仍是完整压缩包；要看完整清单请在本地解压。

### Q17. 截图/封面上传失败

- **现象**：提示不是有效图片、不支持的格式、超过 5 MB 或像素数超限。
- **原因**：平台**按真实图片格式**校验（仅 PNG / JPG / WEBP / GIF），单张 ≤ 5 MB，解码像素数有上限；把其他文件改名成 `.png` 会被识别；截图最多 8 张。
- **怎么办**：用图片工具转换格式并压缩到 5 MB 以内；删除不需要的截图后重试。

### Q18. 提交后门户上搜不到自己的工具

- **现象**：已提交审批，但门户里没有。
- **原因**：这是**预期行为**——`草稿`、`待审批`、`已驳回`、`已下架` 都不在门户展示，只有审批通过后才出现（开启自动放行或在免审白名单中则提交即发布）。
- **怎么办**：到 `我的工具` 页看状态；显示 `待审批` 就等待审批管理员处理。平台**不会主动通知**审批结果，需要自己回来看。

### Q19. 在线工具提示 URL 不合法 / 表单校验失败

- **现象**：保存或提交时报 `400 VALIDATION_ERROR`，常见提示有「webapp 类型必须填写 URL」「URL 必须以 http:// 或 https:// 开头」「简介不能超过 500 字」「工具名称最多 128 个字符」「分类不存在或已停用」。
- **原因**：`在线工具` 类型的 `工具 URL` 是必填项，且必须**以 `http://` 或 `https://` 开头**；`健康检查 URL` 若填写也必须符合同样规则。其余是字段长度或分类被停用导致。
- **怎么办**：补全或修正 URL（注意不要只写主机名，也不要写 `ftp://`）；按提示调整字段长度；分类报错时在编辑页重新选择一个可用分类（原分类可能已被管理员停用）。
