## 任务

### F1 · 副标题

位置（§27.4 已裁定，照做）：

- **门户页 hero 区**：现有 H1「发现内网工具与 Skill」**下方一行**
- **登录页**：站点名**下方一行**
- **不要放进顶栏** —— 顶栏高 56px，已容纳 logo、搜索、主题、用户菜单，塞不下

**为空时完全不渲染**（不留空元素、不留空白间距）。取值 `meta.site_subtitle`。

### F2 · 页脚

**新建一个页脚组件**，显示在**仅门户列表页与工具详情页**（§27.4）。
**不要**加到登录页、个人中心或管理台。

字段与渲染规则：

| 来源 | 渲染 |
| --- | --- |
| `footer_org` | 运营方（纯文本） |
| `footer_contact_email` | 支持邮箱 → **`mailto:` 链接** |
| `footer_contact_phone` | 内线电话 → **`tel:` 链接** |
| `footer_notice` | 备案号 / 版权声明（纯文本） |
| `app_version`（已有字段） | 版本号，如 `v1.0.0` |

**三条硬要求**：

1. **★ 4 个配置字段全为空时，整个页脚不渲染。** 版本号**不算**判断依据 ——
   只看那 4 个字段。这样既有部署不配置时视觉零变化。
2. **★ 邮箱/电话必须防御性降级**：值不像邮箱/电话（含空格、中文、多个 `@`、
   带奇怪字符等）时**退化为纯文本**，不得渲染出坏链接。
   管理员填错一个字符不该让页脚出现一个点不开的链接或崩掉。
3. 语义用 `<footer>` + `aria-label="站点信息"`；主题三态与对比度都要达标。

### F3 · 标签页标题跟随站点名

`document.title` 要跟随 `portal.site_name`，未配置时用既有默认值
（`useMeta.ts` 的 `DEFAULT_SITE_NAME`）。

- **这是修一个已实测的缺陷**（§27.5 约束 2），不是新功能。
- 最低要求：**页面加载后**标题正确。**不要求**改设置后不刷新即时更新。
- **不要**把站点名硬编码进 `index.html` 之外的地方；`index.html` 里那个
  静态 `<title>` 可以保留为**首屏兜底**（JS 未加载完时显示它），
  但 JS 跑起来后必须被设置值覆盖。

### F4 · 类型 / mock / e2e

1. `src/api/types.ts` 的 `Meta` 补 5 个字段（照 §27.3）。
2. `src/mocks/handlers.ts` 的 `/meta` mock 补这 5 个字段
   （默认空串，与后端一致）。**另需能让 e2e 构造「已配置」的场景** ——
   怎么做你定，但要让「副标题与页脚在有值时正确渲染」可测。
3. **新增 e2e**，至少覆盖：
   - 未配置时：**副标题不渲染、页脚不渲染**（这是「零变化」的保证）
   - 配置后：副标题出现在门户与登录页、页脚出现在门户与工具详情页
   - **页脚不出现在登录页与 `/admin`**（范围裁定）
   - 邮箱/电话正常时是 `mailto:` / `tel:`，**填错时退化为纯文本**
   - 标签页标题等于配置的站点名
